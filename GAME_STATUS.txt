RELEASE RULES
- Never patch main blindly. Validate all source text and file sizes; reject
  empty engine files, incomplete script loading, missing assets and syntax errors.
- For significant changes: stage -> test Play/Skip/transition/run/crash/restart
  on iPhone -> promote -> test production -> retain an immediate rollback.
- Do not overwrite the shop calibration JSON when editing engine/intro features.
- Use accurate cache-version changes for modified scripts and images.
- GitHub history is the recovery path; if an installer errors, inspect the
  repository before retrying because some commits might have succeeded.
- Report statuses honestly: CODE CHECKED, STAGED, PHONE-TESTED, LIVE-VERIFIED.

All developer handoffs must explain exact changed files, what is deployed,
what still needs testing, and how to revert without technical guesswork.
